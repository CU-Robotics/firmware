# VN100 sensor wrapper

`src/sensors/vn100.hpp` adapts the public `vn::Serial` interface in
`libraries/vn100/protocol` to the firmware's `Sensor` interface. The library
files remain unchanged. Configuration, callback routing, and cached measurements
live in the wrapper under `src/sensors`.

The original high-level `VN100` class exposes only `loop()` and keeps its parsed
readings private. This wrapper uses the library's public register commands and
binary parsers directly so callers can access measurements without modifying
that class or accessing private members.
The default UART is Teensy `Serial3`; pass a `HardwareSerial&` to select another
UART. The wrapper configures output on **VN100 serial port 2**, regardless of
which Teensy UART is selected. The UART must outlive the wrapper and be dedicated
to this device.

```cpp
#include "sensors/vn100.hpp"

vn100 imu(Serial3);

void setup() {
    imu.init();
    if (!imu.is_initialized()) {
        Serial.println("VN100 setup failed");
        // Retry init() explicitly when appropriate for the application.
    }
}

void loop() {
    static uint32_t last_poll_us = 0;
    const uint32_t now = micros();
    if (static_cast<uint32_t>(now - last_poll_us) < 1000) {
        return;
    }
    last_poll_us = now;
    imu.read();

    const auto &data = imu.get_data();
    if (data.imu_valid) {
        const float gyro_z = imu.get_gyro_Z(); // rad/s
        // Use gyro_z in the application's control or estimation code.
        (void)gyro_z;
    }
    if (data.attitude_valid) {
        const float yaw = imu.get_yaw(); // degrees
        // Use yaw in the application's control or estimation code.
        (void)yaw;
    }
}
```

`init()` performs the blocking UART configuration handshake. Repeating it after
success is harmless. `read()` polls incoming packets only after successful
initialization, so a failed connection does not cause repeated blocking setup
attempts in the control loop.

The acceleration, gyro, and temperature getter names follow the existing IMU
wrappers. Acceleration is in m/s², angular rate is in rad/s, temperature is in
degrees Celsius, and yaw/pitch/roll are in degrees. Getters read the wrapper cache
without initiating UART transactions.

`get_data()` also exposes magnetic field, pressure, quaternion, NED linear
acceleration, saturation flags, and independent IMU/attitude timestamps in sensor
startup nanoseconds. Each packet group updates independently. Its validity flag
means at least one valid packet has arrived; it does not expire when the device
disconnects. Use timestamp changes to detect new samples and an application
timeout to detect stale data. Values are zero-initialized before reception.
The returned reference changes as packets arrive; polling and copying must be
synchronized if data is shared with an ISR or another thread.

Initialize and poll all wrappers from the same foreground thread, outside ISRs.
The library's callback has no context argument, so `read()` temporarily identifies
the receiving wrapper while the library synchronously processes its UART input.
Multiple wrappers can be polled sequentially on separate UARTs.

The wrapper inherits the default no-op `provide_isr_map()`. `send_to_comms()` is
also a no-op because the shared firmware/Hive protocol has no VN100 telemetry
type. `SensorManager` does not yet construct this sensor from robot config;
instantiate and poll it explicitly as above until that protocol/config support
is added.

Run `bash tests/vn100/run.sh` for host packet/wrapper tests and `make build` for
the Teensy firmware build. Host tests use a simulated UART to exercise successful
and failed configuration, baud-rate changes, retries, fragmented/corrupt packets,
and independent readings from multiple wrappers. They do not validate physical
hardware.
